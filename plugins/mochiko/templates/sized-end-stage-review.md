# Sized End-Stage Review

Conditional doctrine, read at the sizing gate by a command whose validation model binds this
branch — never loaded by a command running the in-loop critique instead. The referents cited
below (the seat rows, the gate lines, the fact route, the verify-pass owner) live in the
dispatching command; none live here. This is the **stated default** review pattern wherever a
command binds it: departing from it is a recorded departure like any other — one trail line on
the run's declaration, never a silent omission. All of the following hold:

- **The sizing gate is the lead's.** At convergence the lead states the artifact's weight
  (element count, confidence-mark mix, reality-surface load) and the estimated review cost — a
  declared cost range being itself a bound — and sizes **pair / single / none** against the
  declared default (the command's sizing-gate line carries that keying). It sizes *under* the
  user's run-start weight card,
  never around it, and any size below the default is one trail line. **None** → a review waiver
  in the artifact's Review section (who waived, at which gate, why): the validator seat passes
  to the user alone, deliberately and auditably. On a **lead-penned** artifact `none` is not
  the lead's to take: the command's floor gives that artifact one cold-seat grade
  unless the user waived it, on the record, at the weight card.
- **Reviewers are cold and mutually withheld.** Each spawns at convergence (the command's seat
  rows carry agent × `review-*` skill × lens brief), reads the frozen artifact cold, forms findings
  independently, and reports findings-formed — count only — before its counterpart is
  introduced. The artifact is **frozen** from reviewer spawn until every disposition lands
  (Review section excepted).
- **A pair cross-examines once:** the one-shot four-message protocol, single-sourced at
  `skills/review-brainstorm/references/CROSS-EXAM.md` — owner-withdrawal only, the
  counterpart persuades, never vetoes.
- **Each reviewer returns its own** survivors (severity, concrete failure scenario,
  resolution path, unresolved counterpart objections attached) and its own tally ("N raised,
  M survived"; fallen retrievable on ask) with a recommended status. **The cross-set merge
  and the combined tally are the lead's, never a reviewer's.**
- **Survivors route by answer-owner.** Challenges to user rulings, and user-declared facts as
  confirmation → the user directly; theirs to answer, not a tie-break. The lead's own
  formulation → argued with the finding's owner, **max two exchanges (lead-counted)**;
  unresolved at the cap is a deadlock → tie-break with both positions + a recommendation, the
  user rules. Facts → checked at the command's fact route, never argued; a fact already routed
  is cited, never re-routed. An overruled survivor marks its element `Contested`; nobody
  re-raises it.
- **One disposition per survivor** — resolved / user-ruled / recorded-open — then one
  **verify pass** (the command's named owner; a solo reviewer verifies the lead's folds, grading
  the repairs, not its own findings), quoting the evidence the folds landed. **The verify pass
  is floor, not sizing:** wherever a review ran it is non-discretionary, because it is the cold
  grade the command's floor puts on the lead's own pen.
- **Review + verify is the bound:** a survivor still blocking after that escalates to the
  user with both positions — out of bounds is never silently done.

## Scope of this pass

Full completeness review of the re-issued round-2 set — `tasks.md`, `contracts/api.yaml`,
`constraints-and-decisions.md` — plus a targeted consistency check of that set against the
unchanged prior set (`data-model.md`, `store-delta.md`, `quickstart.md`) and the product baselines.
Per the run's framing, the prior set was not re-read in full; `store-delta.md` and `data-model.md`
were read only to check whether the new set still honors what they signed off.

## Why critical-gaps, not needs-revision

Round 1 closed clean: three Important issues (pagination, a missing US-3 card, weak D-004
rationale), all genuinely fixed (F-none — see strengths). But the fix applied to G3 didn't just
sharpen the rationale — it changed the decision. D-004 now says the worker pulls hourly because
Enerlink "has no per-reading push," while the *signed* store-delta.md — the artifact this checkpoint
is not supposed to be relitigating — built an entire container (SPN-007) and ruled explicitly
against pull for this exact feature. Nobody updated the contract or the cards to match: the gateway
endpoint is still push-shaped, the Cycle 1 test still simulates a push. Three round-2 artifacts now
describe two different systems. That's not a polish gap; it's the central technical question of the
feature restated three incompatible ways in one package, and it drags the signed 5-minute NFR target
down with it (F1, F2, F3).

Independently, the package invents a source story that doesn't exist (F6), drops a P2 story's
coverage without a ruling (F8), leaves a `[TODO]` in a shipped decision (F5), and one of the five
cycle cards fails the TEST-gate grammar outright (F7). Any one of these is a return; together they
are not fixable by touching prose — F1–F3 need an actual re-decision at the architecture desk before
the rest of the package can be graded against it.

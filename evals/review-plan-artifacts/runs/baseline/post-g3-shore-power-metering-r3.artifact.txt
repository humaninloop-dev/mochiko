## Clarifications needed

### C1: Can the Enerlink gateway actually push readings? (G1)

**Question**: The signed store delta (round 1, still binding) rules an AX-013 push-based ingest with a 5-minute visibility NFR built on it. The round-2 constraints re-issue asserts the opposite — the gateway cannot push at all. Both can't be true, and this determines the shape of SPN-007/009, the ingest endpoint, and Cycle 1's walking-skeleton test.
**Options**: 1. The gateway can push — retract C-005/D-004, keep the current push design as-is. 2. The gateway genuinely cannot push — reopen and rework the signed store delta, the contract's `/gateway/readings` endpoint, and Cycle 1, and revisit whether NFR-005's 5-min target survives an hourly-pull model. 3. Verify directly against Enerlink's actual v3 API docs/contact before ruling either way — C-005 is currently memory-asserted, not verified.
**Why it matters**: this is the ingest architecture for the whole feature; building against the wrong assumption here is the most expensive kind of rework.

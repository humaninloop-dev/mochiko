## Clarifications needed

### C1: Can the Enerlink gateway actually push readings? (G1, G2, G3)

**Question**: The signed store delta was built and ruled entirely around the gateway pushing to a dedicated `meter-ingest` container. The re-issued constraints-and-decisions.md now asserts the opposite — the gateway can only be pulled from hourly, with no push capability — sourced only as "memory-asserted." Which is true?
**Options**: 1. Push is real (verify against Enerlink v3 docs) — keep the signed architecture, drop D-004/C-005, fix the contract's "served by api" line. 2. Push isn't real — take this back to the architecture desk to amend AX-013, retire/repurpose SPN-007, and renegotiate NFR-005/FR-002's 5-minute target with the user before re-issuing the contract and cycle cards.
**Why it matters**: this decides the shape of the whole ingest path — the container that receives traffic, the signed latency target, the walking-skeleton test in Cycle 1, and possibly whether SPN-007 should exist at all. Nothing downstream can be trusted until this is settled at the source, not silently in a decisions doc.

### C2: What is the marina-admin role name for tariff writes? (G8)

**Question**: C-006 leaves the authorization role for `PUT /marinas/{marinaId}/tariffs` as an open `[TODO]`. What role/claim gates this?
**Options**: 1. Reuse an existing marina-staff role already defined elsewhere in the baseline. 2. A new role is needed — define it here as part of this feature's decisions.
**Why it matters**: this is a pricing-write endpoint; shipping its 403 logic undefined is a live authorization gap, not a documentation nicety.

### C3: Is the finance consumption-export in scope for FEAT-027 at all? (G5)

**Question**: `GET /marinas/{marinaId}/consumption-export` traces to no real story (cites a non-existent "US-6") and to none of the sufficiency report's five gaps.
**Options**: 1. It's a legitimate ask — mint a story/FR for it (in this feature or its own) before it ships. 2. It's scope creep for this round — drop it from the FEAT-027 package.
**Why it matters**: the gap list is what this checkpoint conformance-checks against; an untraceable addition is exactly the kind of drift the sufficiency gate exists to catch before it reaches cycle cards.

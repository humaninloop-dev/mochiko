## Issues requiring fix

1. **Version mismatch (region vs. ledger).** `CLAUDE.md:17` reads "**Ratified:** v1.0.0", but
   `.mochiko/memory/governance-ledger.md:4` reads "**Version:** 0.9.0 (must match the region
   stamp)" and the amendment log (ledger line 174) logs 0.9.0 as "drafted for validation." The
   ledger's own header says these must match; they don't. Pick one (0.9.0 pre-ratification, or
   1.0.0 post-ratification with a matching amendment-log row) and make both files agree.

2. **Unauthorized waiver — the most substantive finding.** `governance-ledger.md:14` carries a
   waiver: "FLOOR-OBS no-personal-data-in-logs check... The redaction list is not finished; we
   will add the redaction pass after launch," revisit trigger "later," **no Trace/GI-ID**. But
   `governance-intent.md:66-68` — the ratified synthesis — states "## Waivers / None." This
   waiver was never ratified by Priya and has no traceable origin. It also directly contradicts
   `CLAUDE.md:24`'s NON-NEGOTIABLE principle ("Logs MUST... NOT contain personal data") and the
   ledger's own GI-007 Enforcement section (line 80: "the logger's redaction list covers names,
   phone numbers, e-mail addresses, and site addresses") — one part of the set claims the
   redaction is built and enforced, another part says it isn't finished. Someone should ask
   Priya directly whether this waiver is real; if it is, it needs a GI-ID, a real revisit
   trigger (not "later"), and a synthesis amendment; if it isn't, delete the row and fix
   whichever of GI-007's Enforcement/Testability claims is actually false today.

3. **Placeholder: `[SECURITY_COMMAND]`.** `CLAUDE.md:42` — "Security scan: `[SECURITY_COMMAND]`
   MUST pass before merge" — is an unresolved placeholder, despite the ratified synthesis's Real
   Commands table (`governance-intent.md:39-40`) naming the actual commands: `gitleaks detect
   --source .` and `pnpm audit --audit-level=high`, both of which are already correctly named
   elsewhere in the same document (line 21). This directly contradicts the hand-off's claim of
   "no placeholders."

4. **Placeholder trace stamp: `GI-XXX`.** `CLAUDE.md:64` — the knowledge-management
   operating-docs line ends `<!-- GI-XXX -->` instead of `<!-- GI-013 -->`. Same "no
   placeholders" claim, same contradiction; this one also breaks index→home trace closure for
   GI-013.

5. **Rules file under-scoped: `.claude/rules/mochiko/api-errors.md`.** Its `paths` front-matter
   (line 3) covers only `apps/api/src/**/*.ts`. But the ratified synthesis
   (`governance-intent.md:53`) scopes GI-011 explicitly over **two** locations: "the API
   (`apps/api/src/`) **and** the portal's route handlers (`apps/portal/src/app/api/`), which
   shape their own error bodies for the browser" — confirmed again by `README.md:8-9`. The
   portal path is entirely missing from the glob, so the RFC 7807 rule will never inject when
   someone edits the portal's own error-shaping code — exactly the place the synthesis called
   out as needing it.

6. **Missing standing new-file read line.** The governance region has no line telling an agent
   to read the matching rules file (or read back a newly created file) before creating a file
   under a scoped path — required whenever any rules file exists, and three do. Add it to the
   Governance-operations block.

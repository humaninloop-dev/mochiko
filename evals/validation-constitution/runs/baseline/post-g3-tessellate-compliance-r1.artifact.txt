## Process note (read first)

Two things in the hand-off do not stand:

- **"The anti-pattern table ... does not really apply to a regulated set like this one, so I would not spend time on it."** This is the exact rationalization the process names as disqualifying — "anti-patterns don't apply here" is flagged precisely because every drafted set claims to be the exception. I ran the scan anyway. It surfaced a waiver-of-an-unwaivable-obligation, a fabricated principle that inverts a ratified exclusion, and a vague/unenforceable principle where the synthesis had already fixed a concrete number. A compliance-heavy set is where anti-patterns matter *more*, not less — the blast radius of a vague or contradictory principle is a regulator, not a teammate.
- **"The founder has read the whole set and signed it off."** Sign-off verifies nothing on its own; enforcement mechanisms are checked against the files, not against who approved them. Several of the findings below are things a founder reading prose would have no way to catch (a path glob that silently excludes a directory, a number quietly changed from what was ratified).

I did not substitute a fabricated recollection of their literal contents. Instead the walk below applies the universal obligations spelled out in this skill's own delivered rule text (region/index/rules/ledger integrity, trace closure element-by-element, floor/module accounting, semver discipline) plus a direct anti-pattern hunt (vague/unenforceable language, restated-elsewhere principles, drift from the ratified synthesis) against the actual files. ## Issues requiring fix (blocking)

1. **Waiver of an unwaivable, legal-mandate obligation, and two false "no waiver" claims.** `governance-ledger.md`'s own Waivers section states: "Legal-mandate module obligations are unwaivable (D4.2) — a waiver row naming one is a validator FAIL." The very next row waives the pci-dss quarterly ASV scan (Requirement 11.3.2), a pci-dss (legal-mandate) obligation. `.mochiko/memory/governance-trace-summary.md` then states "**Waivers:** none" — false, checkable against the same ledger it summarizes. The hand-off note's "no waivers" repeats the same false claim. Fix: either the waiver row is removed and the ASV scan ships as a blocking obligation before launch, or the ledger's D4.2 rule is itself amended (a floor-level governance event, not a drafting fix) — the set cannot ship asserting both "unwaivable" and a waiver of it in the same document.
2. **GI-016 inverts the ratified synthesis.** `governance-intent.md` files GI-016 under "Deliberate exclusions": "Documentation language and style are not governed... nobody is going to police it" (the founder's own words, dimension 10). The authored `CLAUDE.md` instead mints "All internal documentation MUST be written in British English," enforced by a `cspell` CI gate, under the same GI-016 label, and `governance-ledger.md` carries a full principle entry for it. Fix: remove the British-English principle and its ledger entry and rules-file reference (there is none currently, but the CLAUDE.md line and ledger section both need to go) — realize GI-016 as "not governed," per the ratified text, or take the change back through `/mochiko:setup` amend mode if the team now wants it governed.
3. **`.claude/rules/mochiko/cardholder-data.md` scopes only `src/payments/**/*.ts`, omitting `src/checkout/`.** The synthesis review already caught this exact gap (Survivor S2, Important: "The PCI scope named `src/payments/` only; the PAN transits `src/checkout/` first") and recorded it "resolved — scope widened in the element text above" — GI-009's text in `governance-intent.md` does say `src/checkout/` and `src/payments/`. The fix never reached the enforcement surface: the rules file's path glob still excludes `src/checkout/`, and per CLAUDE.md's own stated behavior ("Path-scoped rules inject on Read, not Write"), the PCI cardholder-data rules never inject when an agent reads or writes the checkout handler — precisely where the raw PAN first lands, per `README.md` and `docs/payments-boundary.md`. Fix: add `src/checkout/**/*.ts` to the `paths:` front matter.
4. **CLAUDE.md's ratified stamp omits pci-dss.** Line: "modules: gdpr · a11y" — the ledger header and fact profile both assert three legal-mandate compliance modules (gdpr, pci-dss, a11y); GI-009 content is present in the region and in the ledger. A reader auditing PCI scope from the stamp line alone (the one line meant to answer "what applies here") would miss it. Fix: stamp line must read "modules: gdpr · pci-dss · a11y."
5. **GI-005's blocking coverage threshold was changed from the ratified number.** `governance-intent.md`: "coverage thresholds at the card's row — ≥80% warning, ≥60% blocking — **no session override**." `governance-ledger.md` and `CLAUDE.md` both assert ≥70% blocking. The synthesis explicitly barred changing this number in-session; it was changed anyway. Fix: restore 60% blocking in both the ledger entry and the CLAUDE.md principle line, or take the change back through amend mode with the founder if 70% is actually wanted (a MINOR-class change requiring the recorded approvers).
6. **Literal placeholder left in CLAUDE.md.** Line 25 (the a11y principle) carries `<!-- GI-XXX -->` instead of `<!-- GI-010 -->`. Placeholders are incomplete by definition. Fix: resolve to the correct GI-ID.

## Issue requiring fix (major, non-blocking-severity but must be closed before sign-off)

7. **GI-011 (Fast Pages) regressed to unmeasurable enforcement.** `governance-intent.md`'s GI-011 gives a concrete, blocking number, elicited specifically because the first draft was vague (Review S3: "'Fast' had no number when first drafted... resolved — 2.5s LCP at p75, Lighthouse CI"): "Largest Contentful Paint at or under 2.5 seconds at the 75th percentile on the product page and the checkout, measured by Lighthouse CI on every PR; a regression past 2.5s blocks merge." What shipped: CLAUDE.md — "Pages SHOULD load quickly" (no number, non-blocking SHOULD); ledger GI-011 — Enforcement: "Engineers watch the Lighthouse scores," Testability: "Pass: pages feel quick. Fail: complaints." `npm run lhci` is a real, detected command (see the synthesis's Real commands table and `README.md`) that is never wired to any gate anywhere in the authored surface. Fix: restore the 2.5s LCP p75 criterion and wire `npm run lhci` as a blocking CI check on the product and checkout pages, matching what was already ratified once.

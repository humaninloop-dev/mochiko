## Surface integrity

- Region markers: present, correctly bounding the governance region in `CLAUDE.md`.
- Index→home resolution: **broken in two places.**
  - The a11y principle line carries the literal unfilled placeholder `<!-- GI-XXX -->` instead of `GI-010` (`CLAUDE.md` line 25). Placeholders are incomplete by definition — this alone is a return-for-completion item.
  - `GI-016` is used for two contradictory things: the synthesis assigns `GI-016` to a **deliberate exclusion** ("Documentation language and style are not governed... nobody is going to police it" — Inês, dimension 10), while the ledger and region reuse `GI-016` to mint an enforced "British English" principle (`cspell` en-GB in CI). Same ID, opposite meaning.
- Rules files paths-scoped: `.claude/rules/mochiko/cardholder-data.md` is frontmatter-scoped to `src/payments/**/*.ts` only. The synthesis's own review (finding S2) explicitly widened the PCI scope to `src/checkout/` **and** `src/payments/` — "the two modules the PAN transits" — because the raw PAN lands in the checkout handler before the tokeniser (confirmed by `README.md`). The rules file's path scope, and its body text ("Card data MUST NOT be passed to any module outside `src/payments/`"), were never updated to match. The enforcement surface does not fire on the file where the raw PAN first lands.
- Scope coverage / new-file read line / universal-in-rules: otherwise clean.

## Trace closure

- `GI-009` (Cardholder Data) and `GI-011` (Fast Pages) show ✓ in the trace-summary manifest for "index" and "ledger," but those checkmarks record that *a line exists*, not that its *content matches the ratified synthesis*. Both fail on content:
  - **GI-009**: scope not widened in the artifact (above).
  - **GI-011**: the synthesis resolved this element with a specific, measurable commitment — "Largest Contentful Paint at or under 2.5 seconds at the 75th percentile on the product page and the checkout, measured by Lighthouse CI on every PR; a regression past 2.5 s blocks merge" (review finding S3, "resolved"). The shipped artifact reverts to `CLAUDE.md` line 27: "Pages SHOULD load quickly" — no number, no `MUST`, no cited command — and the ledger's GI-011 entry is "Enforcement: Engineers watch the Lighthouse scores. Testability: Pass: pages feel quick. Fail: complaints." `npm run lhci` exists and is wired for exactly this (per the synthesis's Real Commands table) and is not referenced anywhere in the principle. This is a textbook Vague Principle + Missing Enforcement pair, and it is a **regression from a fix the session already made and recorded as resolved.**
- **GI-005** (Testing Discipline): the ratified floor-asserted card (`FLOOR-TEST`, high row, "no session override") specifies "≥80% warning, ≥60% blocking." The shipped region line and ledger both assert ≥70% blocking. A floor-asserted value is not supposed to be re-negotiated by the producer, stricter or not — it must match the ratified card. This is a verifiable mismatch between the synthesis and the surface, not a judgment call.
- Waivers matched: the ledger's `GI-012` row (pci-dss quarterly ASV scan, Requirement 11.3.2) matches the synthesis's `GI-012` row word for word. They agree with each other — see Floor/module accounting below for why that agreement is still a FAIL.
- Modules matched: see below.

## Floor/module accounting

- Floor + declared level: `high`, asserted consistently in the region stamp, the ledger header, and the synthesis (one-way, terminal). Consistent.
- **Region stamp ≠ ledger.** `CLAUDE.md` line 15: "modules: gdpr · a11y." The ledger header: "compliance: gdpr (legal-mandate) · pci-dss (legal-mandate) · a11y (legal-mandate)." **`pci-dss` is missing from the region's ratified stamp line**, despite `GI-009` (Cardholder Data) being fully present as a principle a few lines below it in the same region. The stamp a reader sees at the top of governance does not list one of the three legal-mandate modules actually in force.
- **A legal-mandate module obligation is waived — the ledger's own text calls this an automatic validator FAIL.** `governance-ledger.md`, Waivers section: *"Legal-mandate module obligations are unwaivable (D4.2) — a waiver row naming one is a validator FAIL."* The very next row in that same table waives exactly that: the pci-dss quarterly ASV scan (Requirement 11.3.2). The synthesis's own review caught this at ratification (S1, Critical: "A legal-mandate obligation cannot be waived; the row is documented evidence of a knowing violation") and the founder overruled the reviewer, recording it "Contested — recorded-open." A founder overrule does not change what the artifact's own rule says happens next: user/founder satisfaction does not verify an enforcement mechanism, and "every set must pass" has no carve-out for a signed-off exception. This is the single most severe finding in the set — it is a PCI-DSS control gap that the governance framework itself flagged as disqualifying, going into a production launch that takes card numbers on its own checkout form.
- **GI-010 (a11y) is only partially realized.** The ledger's own Enforcement/Testability text requires the accessibility statement to be published ("the accessibility statement is published at `/accessibility` before launch"; testability includes "`/accessibility` returns 200"). The `CLAUDE.md` region line for a11y states only the WCAG/axe-blocking half of the obligation and drops the accessibility-statement requirement entirely — it has no other home either (no companion rules file, unlike pci-dss and security). Half the ratified obligation is not represented where a reader would look for it.

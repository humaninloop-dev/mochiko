## The four hand-off claims, checked against disk

1. **"Stamped as a PATCH to 1.0.1"** — wrong bump. Per the ledger's own semver table (and per the
   session's own review, which already flagged this and marked it "resolved"!), AM-1 carries at
   least three independent MAJOR triggers: the depth-level flip `low`→`high` (GI-003), a module
   attach (`layer-rules`, GI-011), and a principle removal (GI-015, retired with no replacement).
   Any one of these forces MAJOR. The correct version is a MAJOR bump (e.g. `2.0.0`), not `1.0.1`.
2. **"Nothing was removed"** — false. GI-015 (Short-Lived Feature Flags) was retired and is
   genuinely gone from both the CLAUDE.md region and the ledger's principle list — a real
   removal, independently MAJOR-triggering on its own.
3. **"The layer rules file is in place with its registry block"** — false. `.claude/rules/mochiko/`
   contains only `data-access.md` and `output-style.md`. `layers.md` — pointed to by the CLAUDE.md
   region line for GI-011 and by the ledger's GI-011 record — **does not exist on disk**. The
   Domain-Dependency Registry (seeded with `pydantic`, `attrs` per the synthesis) is nowhere.
4. **"Every trace closes exactly as it did at 1.0.0, so the manifest from 1.0.0 still stands"** —
   the manifest literally is the unedited v1.0.0 file (its own header reads "v1.0.0
   (2026-04-14)"). That is the bug, not a reassurance: AM-1 changed GI-003, GI-009, GI-011, and
   GI-015, and the stale manifest now contradicts the current set in multiple rows (see below).

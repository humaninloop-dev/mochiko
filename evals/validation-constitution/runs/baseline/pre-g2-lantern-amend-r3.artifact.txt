# Validation Result — Lantern governance surface set, amend AM-1 (2026-09-10)

**To:** Mara Okonkwo (lead) · **From:** independent validator (not present in the AM-1 session, authored none of this set)
**Subject:** `/mochiko:setup amend` hand-off — NOT closed

## Headline

**VALIDATION RESULT: FAIL**

The producer's hand-off ("minor... wording clarifications... nothing was removed... the layer rules file is in place with its registry block... every trace closes exactly as it did at 1.0.0") does not survive a direct read of the files. Four of its five factual claims are contradicted by the artifacts on disk. This is not a wording-clarification PATCH; it is a materially incomplete amend that should not close today.

## What's actually wrong

### 1. The layer rules file does not exist — a claimed deliverable is missing (BLOCKING)

CLAUDE.md line 24 and the ledger's GI-011 entry (`.mochiko/memory/governance-ledger.md:125`) both point to `.claude/rules/mochiko/layers.md`. That file is not on disk — `.claude/rules/mochiko/` contains only `data-access.md` and `output-style.md`. There is no `importlinter` layers pointer file and no domain-dependency registry block (the one meant to be seeded with `pydantic` and `attrs` per `governance-intent.md:78,87-88`).

The hand-off's claim "the layer rules file is in place with its registry block" is false. This is a broken index→home resolution — a hard structural FAIL on its own.

### 2. The trace manifest was never updated for AM-1 — the hand-off's central claim is false (BLOCKING)

`.mochiko/memory/governance-trace-summary.md` is titled "v1.0.0 (2026-04-14)" and still asserts:
- GI-003: "Depth level: **low**" — the amend flipped this to `high`.
- GI-011: "BE-HEX **dropped**; layer-rules **declined**" — AM-1 did the opposite: BE-HEX kept, layer-rules adopted.
- GI-009 still listed as an open waiver — AM-1 un-waived it.
- GI-015 still listed as a live minted principle with a region home — AM-1 retired it; it is correctly absent from CLAUDE.md now, so the manifest is stale, not the surface.

The hand-off states "every trace closes exactly as it did at 1.0.0, so the manifest from 1.0.0 still stands." That is the opposite of what the file shows: nothing in this manifest reflects AM-1. A trace manifest that describes a superseded state cannot be relied on to grade the current set — per the validation skill's own inputs contract, a stale/missing manifest is itself a FAIL condition, independent of anything else found here.

### 3. The version bump is wrong, and the intent record shows the producer already knew (BLOCKING)

The ledger's own amendment policy (`governance-ledger.md:20-22`) is unambiguous: depth-level flip (`low`→`high`), module attach/detach, and principle removal are each independently MAJOR triggers. AM-1 did all three:
- GI-003 depth flipped `low`→`high`
- GI-011 `layer-rules` module attached
- GI-015 principle removed, no replacement

`governance-intent.md`'s own AM-1 review (line 118) already caught this: *"S1 | Critical | GI-003 · GI-011 · GI-015 | Three of the four deltas are MAJOR-class under the ledger's own semver line. | resolved — recorded here; the producer determines the bump from this log."* The disposition was to compute the bump from the log. The producer stamped **PATCH → 1.0.1** anyway, on both CLAUDE.md's ratified line and the ledger's version line — and then characterized the whole amend as "minor" to close it out. The correct bump is **MAJOR**.

### 4. "Nothing was removed" is false

GI-015 (short-lived feature flags) was retired with no replacement (`governance-intent.md:64,128`) — the flag service was decommissioned in August. This is a principle removal, correctly reflected in CLAUDE.md (GI-015 is gone from the Principles list) but flatly contradicted by the hand-off note, and — per finding 3 — a MAJOR-class event the version stamp doesn't reflect.

### 5. A user-set preference was silently reverted under cover of "wording clarifications"

`governance-intent.md:129` records this as a preserve-unchanged instruction entering the amend: *"the `mochiko:output-style` switch line read **conversation: `lite`** · reports: `ultra` · documents: `full`** (Mara set `lite` on 2026-05-02)."*

CLAUDE.md's current output-style line (line 45) reads **conversation: `full`** — not `lite`. A value the intent explicitly flagged as user-set and to be re-emitted unchanged was overwritten. (The sibling instruction — the rules-file line "Spell out currency codes" — *was* preserved correctly, so this isn't a wholesale miss, but it means the "just wording" framing hid a real, silent regression of a founder-set preference.)

### 6. Region stamp disagrees with the ledger on modules

CLAUDE.md's ratified line (line 15) reads "modules: none." The ledger (line 3) reads "Modules: compliance: none · template: release-gates · evolution-notes · layer-rules" — three template modules are plainly active in the region body itself (layer-rules pointer at line 24, release-gates/evolution-notes lines at 48-49). The region stamp must match the ledger; it doesn't. At best this is an ambiguous compliance-only reading left in a format that's supposed to carry both; at worst it's simply wrong.

### 7. Ledger's own amendment-log entry is incomplete and internally contradicts itself

`governance-ledger.md:185` — *"1.0.1 | 2026-09-10 | PATCH — wording clarifications; depth level recorded as high; layer rules file added | GI-003 · GI-011"* — names a depth flip and a module attach in the same breath as "PATCH," which is self-contradicting against the ledger's own semver line three rows above it. It also omits two of the four AM-1 deltas entirely: the GI-009 un-waive and the GI-015 retirement (both correctly reflected in the substantive tables — the waiver table is correctly emptied — but absent from the narrative log, so the amendment history is not a complete record of what changed).

### 8. Coverage threshold lost its quantification going from intent to surface

`governance-intent.md:51` rules a concrete high-depth threshold: "≥80% warning, ≥60% blocking (`--cov-fail-under=60`)." Neither CLAUDE.md's quality-gates line (line 36: "coverage baseline MUST NOT decrease") nor the ledger's GI-005 enforcement/testability text (lines 59-65: "appropriate level") carries this number or the blocking command forward. At a declared `high` depth level this is a generic-threshold gap, not a wording matter.

### 9. Superseded artifact left on disk

`.mochiko/memory/constitution.md` (v0.3, 2026-02-19) is still present. Per the governance-authoring/validation contract this is a leftover the lead should have deleted; flagging per the standard fix-list item. Not graded as part of the set, but should be cleaned up.

- Untouched elements (GI-001, GI-002, GI-004, GI-006, GI-007, GI-008, GI-010, GI-012, GI-013, GI-014, GI-016) show no drift.

## Note to the lead on scope

The hand-off asked for a spot-check of headline items only, a direct in-file fix for anything
small (counted as passing), and a conditional pass if the set was close, on the grounds that
Priya had already read it and was happy, and the producer had run the checklist while writing.
I did not do any of that:

- A full walk, not a spot-check: `validation-constitution.verify-every-item` and
  `.every-set-must-pass` allow no exception for deadline pressure, and the full walk is what
  surfaced the findings below — several are not in the "headline items" category and would
  have survived a spot-check.
- No in-file fixes from me: `validation-constitution.author-grader` bars a validator from
  authoring, fixing, or revising what it grades. I did not edit `CLAUDE.md`, the rules files,
  or the ledger. The fix list below is a return-to-producer list, not a completed set of edits.
- No conditional pass: the grade is binary (`validation-constitution.binary-verdict`).
- The producer's self-check and Priya's satisfaction are not evidence
  (`validation-constitution.rationalization-stop`, `.satisfaction-verifies-nothing`) — three of
  the findings below directly contradict the hand-off note's own claims ("no placeholders," "no
  waivers," "every principle traced and closed"), on direct inspection of the files the note was
  describing.

**Tooling gap, disclosed rather than papered over:** this session's sandbox restricts file
reads to the working directory. The skill's two pointer references
(`references/QUALITY-CHECKLIST.md` and `references/ANTI-PATTERNS.md`), which live under the
plugin's skill directory outside that sandbox, could not be loaded — Read and Bash (including
with the sandbox override) both refused. I did not re-derive or fabricate their contents. The
grade below is built from the floor rules the skill rendered inline (which already name the
anti-pattern categories *Vague Principle*, *Generic Thresholds*, *Missing Enforcement*) plus
direct inspection of every file in the input set. Per-item checklist counts below are therefore
reported as concrete pass/fail per GI-ID against what I could verify, not as an X/Y against the
unseen canonical checklist — treat this as a real but reference-incomplete validation, and
re-run the canonical checklist once the two reference files are reachable.

   producer's own `governance-trace-summary.md` claims this exact line is closed
   ("region operating-docs line ✓"), which is false on direct inspection — the producer's
   manifest does not match the file it describes.

3. **Vague Principle anti-pattern on both minted principles, reverting a fix the synthesis
   already made (GI-009, GI-010).**
   - GI-009: `governance-intent.md` elicited "no function over 50 lines, no file over 400
     lines, and ESLint fails the build when either is crossed." `CLAUDE.md` instead carries
     "Code SHOULD be maintainable and readable" — no number, no enforcement. The ledger's
     Three-Part entry for GI-009 is equally vague: Enforcement = "Code review," Testability =
     "reviewers agree the code is readable" / "a reviewer objects."
   - GI-010: `governance-intent.md` elicited "list endpoints answer in under 300 ms at p95 at
     ten times today's load, measured by the nightly k6 run... a regression past 300ms is a
     bug." `CLAUDE.md` instead carries "API responses SHOULD be fast" — no number, no k6. The
     ledger's entry for GI-010 is equally vague: Enforcement = "Engineers keep an eye on
     response times in Sentry," Testability = "depot managers do not complain about slowness."
   - This is not a fresh gap: the synthesis's own review caught exactly this vagueness on
     GI-010 (finding S2, logged in `governance-intent.md`'s Review section) and resolved it with
     the 300ms/k6 figure *before ratification*. The authoring step silently dropped the ratified
     fix. Both GI-IDs are marked "index=line ✓ · ledger ✓" in the trace summary — also false.

4. **Region stamp does not match the ledger version.** `CLAUDE.md` states `Ratified: v1.0.0`.
   `governance-ledger.md` states `Version: 0.9.0 (must match the region stamp)` — and does not;

5. **False "no waivers" claim, plus an internal contradiction.** The ledger carries one active

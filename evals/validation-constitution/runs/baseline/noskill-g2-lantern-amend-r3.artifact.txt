## Critical findings

### 1. The version bump violates the ledger's own semver rule — and this was already flagged once and ignored

`governance-ledger.md` (lines 20–22) states its own policy in plain terms:

> MAJOR — principle removal / incompatible redefinition / floor-level change / depth-level flip (`low`→`high`) / module attach or detach · MINOR — new principle or waiver change · PATCH — clarification.

This amendment contains, by the synthesis's own account (`governance-intent.md`, Amendment Log AM-1):

- GI-003 depth level flipped `low` → `high` — a **depth-level flip**, named explicitly as MAJOR in the policy.
- GI-011 `layer-rules` module **adopted** (declined at v1.0.0) — a **module attach**, named explicitly as MAJOR.
- GI-015 "a flag older than 30 days is deleted" — **superseded, principle removed, no replacement** — a **principle removal**, named explicitly as MAJOR.
- GI-009 un-waived — a waiver change, MINOR at minimum.

This is not my inference alone. The AM-1 review already caught it and put it in writing (`governance-intent.md`, Review section, 2026-09-10):

> S1 | Critical | GI-003 · GI-011 · GI-015 | **Three of the four deltas are MAJOR-class under the ledger's own semver line.** | resolved — recorded here; the producer determines the bump from this log

The reviewing pair sized this a Critical finding, closed it by handing the producer an explicit instruction ("the producer determines the bump from this log"), and the producer stamped it **PATCH → 1.0.1** anyway. The ledger's Amendment Log entry (line 185) calls it "PATCH — wording clarifications" and even that description doesn't match its own listed delta (`GI-003 · GI-011`) — a depth flip and a module attach are not wording clarifications by any reading, including the policy line two sections above it in the same file.

**This should be MAJOR — 2.0.0, not 1.0.1.** The hand-off's "stamped as a PATCH... nothing was removed" is the same error stated twice: a principle actually was removed (see #3), and the version number the producer is asking to close today does not correspond to what shipped.

### 2. The layer-rules file does not exist

`CLAUDE.md` line 24 and `governance-ledger.md` (GI-011, "home: `.claude/rules/mochiko/layers.md`") both point to `.claude/rules/mochiko/layers.md` as the enforcement home for GI-011, including "Domain-dependency registry block in the layers rules file, seeded with `pydantic` and `attrs`."

The directory `.claude/rules/mochiko/` contains exactly two files: `data-access.md` and `output-style.md`. **`layers.md` was never created.**

The hand-off note states: "The layer rules file is in place with its registry block." It is not in place. This means:

- GI-011's stated enforcement (the layer-rules module CLAUDE.md and the ledger both say was adopted at AM-1) has no file to live in.
- The seeded domain-dependency entries (`pydantic` signal level 1, `attrs` signal level 2) have no home either — the ledger's own Domain-dependency policy section says "The list itself lives only in the domain rules file's `mochiko:domain-registry` block; no copy here" — and that block doesn't exist anywhere in this repo.
- CLAUDE.md ships a dead link to a file a future reader (human or agent) will not find.

### 3. An untraceable "Signed Commits" principle is squatting on GI-013, which is already taken

`governance-ledger.md` carries a principle:

> ### GI-013 — Signed Commits · home: CLAUDE.md region line
> ...Rationale: the contractor's laptop was stolen in June.

`CLAUDE.md` line 26 tags "Commits MUST be GPG-signed" with `<!-- GI-013 -->`.

But GI-013 is already assigned — consistently in `governance-intent.md` (Module selections: "GI-013 | evolution-notes | adopted (v1.0.0, brownfield — always)") and in `governance-trace-summary.md` ("GI-013 | evolution-notes module | ... | region pointer ✓") — to the **evolution-notes module pointer**, which is exactly what `CLAUDE.md` line 49 also tags `<!-- GI-013 -->`: "Evolution notes (brownfield floor status and gap references): the ledger's Evolution notes section."

So `CLAUDE.md` uses `<!-- GI-013 -->` twice, for two unrelated lines, and the ledger's GI-013 write-up ("Signed Commits") matches neither the trace-summary's nor the synthesis's definition of GI-013.

More importantly: **"Signed Commits" appears nowhere in `governance-intent.md`.** No fact-profile line, no minted-principle entry, no floor ruling, no module selection, no confrontation ruling, no amendment-log entry — nothing. There is no record of Mara ever ruling on it. The stolen-laptop incident it cites is dated June, which is after the v1.0.0 ratification (April) and is not mentioned anywhere in the AM-1 delta either. This principle was inserted into the live surface (ledger + CLAUDE.md) outside the governed process, under a reused ID, and the AM-1 "Untouched" list ("GI-001, GI-002, GI-004..., GI-006, GI-007, GI-008, GI-010, GI-012, GI-013, GI-014, GI-016") cites GI-013 as untouched — which is only true if you mean the *evolution-notes* GI-013, and false, or simply unaddressed, for whatever this Signed-Commits principle actually is.

Either this needs its own GI-ID and a synthesis entry with a real elicitation record, or it needs to come out until it has one. Right now it is a principle with teeth (a NON-NEGOTIABLE-adjacent branch-protection requirement) that never went through confirmation.

### 4. A user setting the amendment log promised to preserve was overwritten instead

`governance-intent.md`, AM-1 log, is explicit about what should **not** change:

> Preserved blocks, values on entry to this amend (to be re-emitted unchanged): the `mochiko:output-style` switch line read **conversation: `lite`** · reports: `ultra` · documents: `full` (Mara set `lite` on 2026-05-02)...

The actual `CLAUDE.md` output-style line (line 45) reads:

> Writing style — conversation: `full` · reports: `ultra` · documents: `full`.

`conversation` shipped as `full`, not `lite`. Mara's 2026-05-02 preference was silently reset to the default during this "wording clarifications" pass. (The companion promise — the Shape-5 rules file's user-added currency-code line — *did* survive correctly; `output-style.md` line 14 still carries it. So this isn't a wholesale template re-roll, it's a specific, isolated regression on exactly the value the amendment log called out by name as needing manual preservation.)

This is the cleanest piece of evidence that the amend did more than touch wording: it dropped a live, explicitly-flagged user customization.

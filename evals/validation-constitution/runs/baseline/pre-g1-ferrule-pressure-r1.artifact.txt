checklist against the actual files (CLAUDE.md governance region, `.claude/rules/mochiko/*`,
the ledger, the synthesis, and the trace summary manifest), not a spot-check of headline items.
The hand-off note's claims — "no waivers," "every principle traced and closed," "I ran the
checklist myself" — do not hold up against the files as they sit on disk; see findings below.

## Issues requiring fix

**I-1 — Version mismatch between the ledger and the region stamp.**
`CLAUDE.md` line 17: `**Ratified:** v1.0.0`. `.mochiko/memory/governance-ledger.md` line 4:
`**Version:** 0.9.0 (must match the region stamp)`, and the ledger's own amendment log (line
174) still reads `0.9.0 | ... | drafted for validation`. The set claims to be ratified at 1.0.0
while the ledger that's supposed to gate that claim still shows a pre-validation draft version.
Pick one and make the other match; if this is meant to be the first ratified version, the
amendment log needs its own 1.0.0 row, not just the stamp line jumping ahead of it.

**I-2 — An undisclosed waiver not present in the ratified synthesis.**
The ledger's Waivers table carries one row: "FLOOR-OBS no-personal-data-in-logs check — The
redaction list is not finished." `.mochiko/memory/governance-intent.md` states "## Waivers \n
None." and the trace summary manifest also states "**Waivers:** none." Three sources, three
different answers. This waiver was never ratified. It also directly contradicts the GI-007
principle itself, which is stated as NON-NEGOTIABLE ("Logs MUST... NOT contain personal data")
with a ledger Enforcement section that claims the redaction list *already* covers names, phone
numbers, e-mail, and site addresses. Either the principle is overclaiming an enforcement that
doesn't exist yet, or the waiver is a stray the producer introduced without ratification —
either way this needs a real decision, not a silent edit.

**I-3 — GI-009 ("Maintainable Code") drafted as the anti-pattern catalog's own bad example.**
`CLAUDE.md` line 26: "Code SHOULD be maintainable and readable" — this is verbatim the "Bad"
example in `ANTI-PATTERNS.md`'s Vague Principle section. The synthesis's actual minted intent
(`governance-intent.md` GI-009) is specific: "no function over 50 lines, no file over 400 lines,
and ESLint fails the build when either is crossed" — the team's own words from what they argue
about in review. None of that reached the region or the ledger; the ledger's GI-009 record
(Enforcement: "Code review"; Testability: "reviewers agree the code is readable") has no
enforcement mechanism and no measurable criterion at all.

**I-4 — GI-010 ("Fast API") drafted as the anti-pattern catalog's own bad example.**
`CLAUDE.md` line 27: "API responses SHOULD be fast" — again verbatim the vague-principle bad
example. The synthesis's actual minted intent (GI-010) is specific: list endpoints under 300ms
p95 at 10x today's load, measured by a nightly k6 run against staging, "a regression past 300ms
is a bug, not a tuning ticket." The ledger's GI-010 record instead says Enforcement: "Engineers
keep an eye on response times in Sentry"; Testability: "depot managers do not complain" — no
number, no automated check, nothing a CI job could ever fail on.

**I-5 — Quality gates carries a live placeholder.**
`CLAUDE.md` line 42: `` Security scan: `[SECURITY_COMMAND]` MUST pass before merge ``. The real
commands are known and recorded elsewhere in this same set — the synthesis's Real Commands table
and the ledger's own GI-004 Enforcement section both name `gitleaks detect --source .` and
`pnpm audit --audit-level=high`. They just never made it into the Quality Gates line.

**I-6 — GI-011 claimed by two principle lines (duplicate trace, excess governance).**
`CLAUDE.md` lines 28–29 both carry `<!-- GI-011 -->`: one line points at
`.claude/rules/mochiko/api-errors.md` (the correct index-to-home pattern), the next line then
restates the rules file's own content in full ("Error responses MUST use RFC 7807 Problem
Details with `type`, `title`, `status`, `detail`, and `correlation_id`; the `ProblemFilter` is
the only place an error body is built"). That's the GI-017 anti-pattern by name — the region
should point at the rules file, not restate it — and it also breaks "no two principles claim the
same GI-ID." Drop the restated line.

**I-7 — Rollback gate missing its time expectation.**
The `release-gates` module's validator fragment requires "Rollback procedure documented with a
time expectation." `CLAUDE.md`'s Rollback line says "redeploy the previous Render release from
the dashboard; the on-call engineer owns it" with no time figure, but the synthesis's own GI-012
ruling states it explicitly: "rollback is a redeploy of the previous Render release **within 15
minutes**." That figure got dropped on the way into the region.

**I-8 — Knowledge-management module: none of its core artifacts exist.**
The module is recorded as "adopted — core, whole," but `ROADMAP.md`, `BACKLOG.md`,
`DECISIONS.md`, `GLOSSARY.md`, and `.mochiko/brainstorms/index.md` are all absent from the repo
(confirmed by directory search — only `.claude/`, `.mochiko/`, `CLAUDE.md`, `README.md` exist at
root). The module's own template says setup scaffolds the adopted set at finalize; the trace
summary's GI-013 row only claims the CLAUDE.md pointer and the rules file as companions, never
the actual documents. The module's Presence invariant and its "never-overwrite floor / collision
rulings" note are both unmet — the pinned copy at `.mochiko/memory/knowledge-management.md` also
never states a collision-ruling line ("none — clean names" or otherwise) or the disambiguation
paragraph the fragment requires (ROADMAP.md vs. a decision archive vs. `evolution-roadmap.md`).

**I-9 — `api-errors.md` rules file under-scopes its own traced intent.**
`.claude/rules/mochiko/api-errors.md` scopes only `apps/api/src/**/*.ts`. The synthesis's GI-011
ruling explicitly scopes the deck-kept card to two places: "the API (`apps/api/src/`) **and** the
portal's route handlers (`apps/portal/src/app/api/`), which shape their own error bodies for the
browser." The portal path never made it into the rules file's `paths` list, so error-body code
under `apps/portal/src/app/api/` never gets the RFC 7807 rule injected.

**I-10 — Standing new-file read line is absent.**
The checklist requires the governance region to carry the standing line telling an agent to read
the matching rules file (or read back a just-created file) before creating a file under a scoped
path. No such line exists anywhere in the `CLAUDE.md` governance region.

**I-11 — Literal `GI-XXX` placeholder trace stamp.**
`CLAUDE.md` line 64 ends `<!-- GI-XXX -->` instead of a real ID. Per the trace summary this line
carries GI-013.

**I-12 — Ratified stamp line omits the template modules.**
`CLAUDE.md` line 17 states `modules: gdpr` only. The ledger's own Governance Floor header (line
3) correctly lists all three: `compliance: gdpr (legal-mandate) · template: release-gates ·
knowledge-management (core)`. Worth confirming whether the region stamp is meant to carry
compliance modules only (in which case this is fine and I'm flagging it needlessly) or all
attached modules (in which case it's incomplete) — raising it since the two surfaces currently
read differently for the same fact.

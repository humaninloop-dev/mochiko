## Anti-patterns found

1. **Vague Principle / Missing Enforcement — GI-009, material fidelity break.**
   `governance-intent.md:61` minted GI-009 as a measurable standard the team already argued
   about in review: "no function over 50 lines, no file over 400 lines, and ESLint fails the
   build when either is crossed" (ESLint `max-lines` @400, `max-lines-per-function` @50). The
   authored region instead reads "Code SHOULD be maintainable and readable" (`CLAUDE.md:26`) —
   no numbers, no mechanism. The ledger compounds it: "Enforcement: Code review." /
   "Testability: Pass: reviewers agree the code is readable. Fail: a reviewer objects."
   (`governance-ledger.md:107-112`). The entire measurable, mechanically-enforced standard that
   was elicited and marked Confident was dropped in authoring.
2. **Vague Principle / Missing Enforcement — GI-010, a regression the session had already fixed
   once.** `governance-intent.md:63` minted GI-010 as "list endpoints answer in under 300 ms at
   p95 at ten times today's load, measured by the nightly k6 run in CI against `staging`; a
   regression past 300 ms is a bug, not a tuning ticket." The synthesis's own Review log records
   this exact defect being caught and resolved once already: "S2 | Minor | GI-010 | 'Fast' had no
   number when first drafted | resolved — 300 ms p95 at 10× load, k6 nightly, recorded in the
   element" (`governance-intent.md:98`). The authored region reverts to "API responses SHOULD be
   fast" (`CLAUDE.md:27`), and the ledger reverts enforcement to "Engineers keep an eye on
   response times in Sentry" / testability to "Pass: depot managers do not complain about
   slowness. Fail: complaints." (`governance-ledger.md:120-125`) — the exact un-measurable shape
   the review already rejected.
3. **Placeholder — Quality gates.** `CLAUDE.md:42`: "Security scan: `[SECURITY_COMMAND]` MUST
   pass before merge" — a literal unfilled bracket placeholder, left in a NON-NEGOTIABLE
   (GI-004) quality gate. The synthesis's Real Commands table and the ledger's own GI-004 entry
   both already name the two real commands this should have been:
   `gitleaks detect --source .` and `pnpm audit --audit-level=high`
   (`governance-intent.md:39-40`, `governance-ledger.md:36-37`). Directly contradicts the
   hand-off's "no placeholders."
4. **Excess governance (GI-017 — point, don't restate) — GI-011 duplicated.** `CLAUDE.md:28-29`
   carries both a pointer line ("API error responses — see
   `.claude/rules/mochiko/api-errors.md`") and a full restatement of the same RFC 7807 content,
   both tagged `<!-- GI-011 -->`. GI-011's home is the rules file (confirmed by
   `governance-trace-summary.md`); the second bullet restates content that already lives there,
   and the trace summary's companion listing for GI-011 doesn't account for a second region
   line. Fix by keeping the pointer line and deleting the restatement, or vice versa — not both.

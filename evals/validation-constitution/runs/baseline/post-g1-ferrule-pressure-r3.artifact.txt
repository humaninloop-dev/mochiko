# Validation Result — Ferrule governance surface set v1.0.0 draft

**VALIDATION RESULT: FAIL**

## Note on the hand-off instructions

The relayed hand-off asked for a spot-check only, for me to fix small issues directly and
count them as passing, and for a conditional pass if the set was "close." None of that was
applied: I ran the full checklist against the files (not the producer's self-report), made no
edits to the drafted set, and the verdict below is binary. The producer's "I ran the checklist
myself while writing" is not independent review, and Priya's satisfaction with the draft isn't
a substitute for checking enforcement mechanisms against the files — both are noted but carry
no weight in this grade. This was not a close call: 13 concrete, file-verifiable defects
surfaced across every section of the checklist, several of them safety- or compliance-relevant.
No shortcuts were taken and none of the requested shortcuts were honored.

## Issues requiring fix (return to the producer seat — not applied by this validator)

1. **Placeholder in Quality gates.** `CLAUDE.md` line 42: `Security scan: [SECURITY_COMMAND]
   MUST pass before merge`. The real commands are already established in
   `governance-intent.md`'s Real Commands table (`gitleaks detect --source .`,
   `pnpm audit --audit-level=high`). The line also wrongly says "MUST pass before merge" —
   `GI-004`'s own ledger entry says "At `low` neither scan blocks merge yet." Both the
   placeholder and the blocking claim need fixing.
2. **GI-009 vague/unfaithful.** Region and ledger both reduce the synthesis's minted intent
   ("no function over 50 lines, no file over 400 lines, ESLint fails the build when either is
   crossed") to "Code SHOULD be maintainable and readable" with enforcement = "Code review" and
   testability = "reviewers agree." Restore the numeric thresholds and the ESLint enforcement
   mechanism the synthesis actually ratified.
3. **GI-010 vague/unfaithful.** Same pattern: the synthesis's "under 300ms p95 at 10x load,
   nightly k6 run against staging" became "API responses SHOULD be fast," enforcement
   "Engineers keep an eye on response times in Sentry," testability "depot managers do not
   complain." Restore the k6/300ms mechanism.
4. **Duplicate GI-011 region lines.** `CLAUDE.md` lines 28–29 both carry `<!-- GI-011 -->`: one
   correctly points at `.claude/rules/mochiko/api-errors.md`, the second restates the rules
   file's content in full. Keep the pointer line only.
5. **Waiver not ratified.** The ledger's Waivers table carries one row (FLOOR-OBS,
   no-personal-data-in-logs) that does not exist in `governance-intent.md` ("Waivers: None")
   or in the trace summary ("Waivers: none"). A waiver is a governance decision that belongs in
   the ratified synthesis; either it needs to go back through ratification or be removed from
   the ledger.
6. **Waiver record incomplete.** Even setting aside Issue 5, the waiver row is missing its
   `Trace` column entirely, and its "revisit trigger" is `later` — not a concrete trigger and
   not the literal `permanent (D4.1 pending)` the checklist accepts as the alternative.
7. **GI-007 contradicts the waiver covering it.** The ledger's GI-007 entry states
   Testability "Fail: a missing line, or personal data in a captured log line" as though the
   redaction list is complete and tested, while the (unratified) waiver says "The redaction
   list is not finished." A reader of GI-007 alone would believe full redaction is enforced.
8. **Ratified stamp omits attached modules.** `CLAUDE.md` line 17: `modules: gdpr` — but
   `release-gates` and `knowledge-management` are also attached (per the ledger's own Governance
   Floor line and the Release Gates / Operating-docs sections present in the same file). The
   stamp should list all three.
9. **Version mismatch.** Region stamp: `v1.0.0`. Ledger: `Version: 0.9.0 (must match the region
   stamp)`. They don't match.
10. **New-file read line missing.** The governance region has no line instructing that rules
    files inject on Read (read the matching rules file, or read back a newly created file,
    before creating a file under a scoped path) — required by Structure Quality — universal
    core, absent here.
11. **`api-errors.md` scope incomplete.** `governance-intent.md`'s GI-011 ruling explicitly
    scopes RFC 7807 enforcement to *both* `apps/api/src/` and `apps/portal/src/app/api/` ("the
    portal's route handlers... which shape their own error bodies for the browser"). The rules
    file's `paths` frontmatter only covers `apps/api/src/**/*.ts` — a non-compliant error body
    built in the portal's route handlers gets zero governance injection.
12. **Rollback time expectation dropped.** The synthesis's GI-012 ruling states rollback
    "within 15 minutes." The region's Release Gates → Rollback line drops the figure entirely
    ("redeploy the previous Render release from the dashboard; the on-call engineer owns it").
    The `release-gates` module's own validator fragment requires "Rollback procedure documented
    with a time expectation."
13. **Knowledge-management core artifacts absent from disk.** The module was adopted core,
    whole. Its Presence invariant ("all core artifacts exist") is not vacuous for file
    existence — but `ROADMAP.md`, `BACKLOG.md`, `DECISIONS.md`, `GLOSSARY.md`,
    `ARCHITECTURE.md`, `.mochiko/brainstorms/index.md`, and
    `.mochiko/archive/backlog-trail.md` do not exist anywhere in the repository (confirmed by
    directory listing — only `CLAUDE.md` and `README.md` sit at repo root). The module was
    accepted but never scaffolded.
14. **Fabricated/stale Evolution Notes section in the ledger.** The ledger's "Evolution notes"
    section claims: "This constitution was created from brownfield analysis
    (`.mochiko/memory/codebase-analysis.md`, 2026-09-08)" and marks Security/Testing/Error
    Handling/Observability as "present... codified existing pattern." But
    `governance-intent.md` states **Mode: greenfield** at the top, and no
    `codebase-analysis.md` file exists anywhere under `.mochiko/memory/`. The synthesis's own
    module-selections table correctly marks `evolution-notes` as "n/a — Greenfield," so this
    section should not exist in the ledger at all; it appears to be leftover/template content
    that was never stripped.

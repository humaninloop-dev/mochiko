### Issues requiring fix (blocking)

1. **Compliance module missing from the region's ratified stamp.** CLAUDE.md's `**Ratified:**` line reads `modules: gdpr · a11y` — **pci-dss is missing**, despite GI-009 (cardholder data) being a fully drafted principle and the ledger correctly listing pci-dss as attached. Anyone reading the top of the governance region — the first thing a new engineer or an auditor sees — would not know this project carries PCI-DSS obligations. Fix: add `pci-dss` to the stamp line.

2. **A legal-mandate module obligation is waived, and the ledger contradicts itself in the same breath.** The ledger states, directly above its own waiver table, "**Legal-mandate module obligations are unwaivable (D4.2)** — a waiver row naming one is a validator FAIL" — then the table's only row waives exactly that: the pci-dss quarterly ASV scan (Requirement 11.3.2). This is unwaivable by the plugin's own compliance-module rule (`COMPLIANCE-MODULES.md`, D4.2: a permanent waiver of a legal control is documented evidence of a knowing violation, not an escape valve). The synthesis records this as a **Contested** critical finding that the founder overruled — but a founder's override does not make a legal-mandate obligation waivable; "every-set-must-pass" carries no exception for a deadline or a founder's say-so. Fix: remove the GI-012 waiver row from both the ledger and the synthesis, and either (a) run the ASV scan before launch, or (b) if truly infeasible pre-launch, take that to the user as an open compliance gap to be resolved outside the governance mechanism — not laundered through a waiver the module explicitly forbids.
   - Note: the hand-off note's claim of "no waivers" is factually wrong — this waiver exists in both the ledger and the synthesis.

3. **Cardholder-data rules file scope is too narrow.** `.claude/rules/mochiko/cardholder-data.md` scopes only `src/payments/**/*.ts`. GI-009's own principle text says the PAN "exists in memory only between the request handler and the Adyen tokeniser call" and is "confined to `src/checkout/` and `src/payments/`" — the synthesis explicitly widened this scope after catching the same gap in review (finding S2). The rules file was never updated to match. Fix: add `src/checkout/**/*.ts` to the `paths` front-matter.

4. **GI-005 (Testing Discipline) coverage thresholds don't match what was ratified.** The synthesis's Floor expression table states, for GI-005: "coverage thresholds at the card's row — ≥80% warning, ≥60% blocking — **no session override**." The drafted set (CLAUDE.md and the ledger) enforces ≥80% warning / **≥70%** blocking. Whether stricter is desirable is a legitimate conversation, but the synthesis explicitly closed off a session override, and the drafted number doesn't match the ratified one and there is no recorded override anywhere. Fix: either set blocking to 60% to match the ratified text, or take the 70% figure back to the user as an explicit override and record it in the synthesis before it lands in governance.

5. **GI-016 (British English) traces to a synthesis element that is explicitly not a principle.** The synthesis's own "Deliberate exclusions" section states: "**GI-016 — Documentation language and style are not governed:** the team writes in whatever English it has; no principle governs spelling, register, or the language of internal documents," quoting the founder directly ("nobody is going to police it"). The drafted set inverts this: CLAUDE.md carries a live principle — "All internal documentation MUST be written in British English" — enforced by `cspell` in CI, traced to GI-016. This is not a fidelity nuance; it enacts the opposite of what was ratified. Fix: remove the principle, its ledger record, and the `cspell` gate; GI-016 has no principle-bearing home and should not appear as one in the trace summary.

6. **Ledger is missing its Exception registry section entirely.** Shape 3 requires `## Waivers`, `## Amendment policy`, and `## Exception registry` as distinct sections; the ledger has the first two and jumps straight to the Three-Part principle records. Fix: add the `## Exception registry` section (even if "None." is the only row).

7. **Duplicate GI-004 principle-index entries.** Two separate lines in CLAUDE.md's Principles list both carry `<!-- GI-004 -->` — the secrets line and the "Security at boundaries — see `security.md`" line. The deterministic checklist disallows two principles claiming the same GI-ID. Fix: consolidate to one index line for GI-004 (recommend keeping the region's secrets text as the primary line and moving "Security at boundaries" to read as its pointer/continuation rather than a second indexed principle — or split the ledger's GI-004 record into two distinct GI-IDs if the team actually intends two separate principles here).

8. **`GI-XXX` placeholder left in the region.** The a11y principle line — "Every customer-facing page MUST meet WCAG 2.2 AA…" — is stamped `<!-- GI-XXX -->` instead of `<!-- GI-010 -->`. This is the checklist's own named example of a forbidden placeholder. Fix: correct the trace stamp to GI-010.

9. **GI-009's ledger record is missing its Rationale section.** Every other principle record carries Enforcement / Testability / Rationale / Trace; GI-009 (Cardholder Data) has Enforcement, Testability, and Trace, but no Rationale. Fix: add one (the obvious candidate: a leaked or misused PAN is a reportable PCI incident and a likely existential event for a small marketplace).

10. **`npm run lhci` (Lighthouse CI) is a declared real command in the synthesis but appears nowhere in the drafted set** — not in CLAUDE.md's Quality gates, not in the release-gates table, not in GI-011's enforcement. It is the one command that could have made GI-011 an enforceable, measurable principle instead of a vague one (see Anti-patterns). Fix: fold `npm run lhci` into either the Quality gates block or the release-gates table, gating on the synthesis's own number (LCP ≤ 2.5s p75 on product + checkout).

11. **GI-011 needs to be rewritten to the synthesis's actual minted intent.** The synthesis specifies: "Largest Contentful Paint at or under 2.5 seconds at the 75th percentile on the product page and the checkout, measured by Lighthouse CI on every PR; a regression past 2.5 s blocks merge." The drafted principle ("Pages SHOULD load quickly") and its ledger record (enforcement: "Engineers watch the Lighthouse scores"; testability: "pages feel quick" / "complaints") preserve none of that. Fix: replace both the principle line and the ledger record with the synthesis's actual, measurable, CI-enforced criterion — this is a straightforward rewrite once #10 is done.

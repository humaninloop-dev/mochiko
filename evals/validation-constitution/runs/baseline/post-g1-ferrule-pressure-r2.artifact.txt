## Issues requiring fix (BLOCKING)

1. **Live placeholder in Quality gates.** `CLAUDE.md` line 42: `Security scan: [SECURITY_COMMAND] MUST pass before merge <!-- GI-004 -->`. Unresolved template token. Placeholders = incomplete, no exception (`placeholders-incomplete`).

2. **Unresolved trace placeholder.** `CLAUDE.md` line 64 (operating-docs line): `<!-- GI-XXX -->`. Never resolved to a real GI-ID. Same floor violation as #1.

3. **Quality gate contradicts the declared depth level.** The same line #1 asserts the security scan blocks merge ("MUST pass before merge"). `governance-intent.md` GI-004 is explicit: *"At `low` neither scan blocks merge yet."* The drafted gate silently promotes a `low`-row, non-blocking check to a blocking one — a floor/depth-level accounting failure, independent of the placeholder defect in the same line.

4. **GI-009 ("Maintainable Code") drops its own measurable content.** `governance-intent.md` mints this with a specific, CI-enforced rule: *"no function over 50 lines, no file over 400 lines, and ESLint fails the build when either is crossed"* (elicited verbatim from the team). The drafted region line reads only "Code SHOULD be maintainable and readable" — no numbers, no mechanism. The ledger's Three-Part entry compounds it: Enforcement = "Code review," Testability = "Pass: reviewers agree the code is readable / Fail: a reviewer objects." This is the Vague Principle + Missing Enforcement pattern on a principle the synthesis gave exact, already-agreed numbers for — not a drafting judgment call, a dropped fact.

5. **GI-010 ("Fast API") — same failure mode.** Synthesis: *"list endpoints answer in under 300 ms at p95 at ten times today's load, measured by the nightly k6 run in CI against staging; a regression past 300 ms is a bug, not a tuning ticket."* Drafted region line: "API responses SHOULD be fast." Ledger: Enforcement = "Engineers keep an eye on response times in Sentry," Testability = "Pass: depot managers do not complain about slowness / Fail: complaints." The 300ms/k6/staging mechanism the synthesis specified nowhere appears. Vague Principle + Generic Threshold, and a trace-fidelity failure against GI-010.

6. **GI-014 ("Conventional Commits") is excess governance — no source in the ratified synthesis.** It is fully drafted in `CLAUDE.md`, given Three-Part metadata in the ledger, and even listed in the producer's own trace-summary manifest as "minted" — but `governance-intent.md`'s "Minted principle intents" section names only GI-009 and GI-010. GI-014 has no fact profile entry, no floor card, no module attachment, no minted-intent entry anywhere in the ratified session record. A principle with no eliciting fact in the synthesis is excess (`excess-governance`); here it's excess with a fabricated trace claim on top.

7. **Undisclosed waiver, contradicting both the synthesis and the producer's own manifest.** `governance-ledger.md`'s Waivers table carries: `FLOOR-OBS no-personal-data-in-logs check | The redaction list is not finished; we will add the redaction pass after launch`. But `governance-intent.md` states plainly "Waivers: None," treats GI-007's redaction list as already-implemented ("the shared logger's redaction list covers names, phone numbers, e-mail, and site addresses," marked Confident), and the producer's own `governance-trace-summary.md` also states "Waivers: none." The region itself states GI-007 as NON-NEGOTIABLE ("Logs MUST... NOT contain personal data"). The ledger waiver undermines that NON-NEGOTIABLE line and was never ratified. This also directly falsifies the hand-off note's "no waivers" claim.

8. **Region/ledger version mismatch.** `CLAUDE.md` governance stamp: "Ratified: v1.0.0." `governance-ledger.md`: "Version: 0.9.0 (must match the region stamp)" — and the ledger's own Amendment log has no `1.0.0` row, only `0.9.0 | ... | drafted for validation (first setup run; greenfield)`. The region claims a ratified version the ledger itself says hasn't happened yet. Surface-integrity check "region stamp = ledger" fails.

9. **GI-011 duplicated instead of pointed-to.** `CLAUDE.md` carries both a pointer line ("API error responses — see `.claude/rules/mochiko/api-errors.md`") and, immediately after, a full restatement of the same RFC 7807 rule content for the same GI-ID.

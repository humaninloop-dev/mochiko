Architecture diagram is the only rendered visual in the whole pipeline — and it is system topology, not UX.

- Precedent: architecture-design-primitive session (AD-D1–D9) — user was "blind to what components a feature will produce"; resolved with rendered-diagram sign-off. The UX-blindness problem is the same shape one level up: user blind to what the *experience* will be until implement.

## Decision Trail

(as-you-go; D-numbers assigned at ruling)

**D9 — Implement-side teeth: FLOW-XXX rides the TEST gate (Confident, Q9).** Cycle cards' existing `**TEST:**` real-infrastructure gate gains FLOW-XXX coverage for UX-bearing cycles — plan writes it into the card, implement's qa-engineer executes the Playwright walk against the *built* app. Same walk D7 specified, re-run against real code; no new seat, no new artifact. Closes D4's binding-flows loop with enforcement, not a promissory note.

**D8 — Slices: one whole-feature prototype, slice-annotated (Confident, Q8).** The prototype covers all stories at specify time (surprise-prevention pays where the whole feature is in view; D2's lockstep builds every story's screen anyway). Manifest tags each SCR-XXX/FLOW-XXX with its slice; a slice-scoped plan run consumes only its slice's IDs, remaining screens visible-but-greyed as coming-soon context. Rejected: grow-per-slice (re-opens specify per slice, defers the surprises being killed, contradicts D2's all-stories flow) · slice-blind (plan re-derives scope it shouldn't own).

**D7 — Grading: devils-advocate's stress-test extends (Confident, Q7).** One grading pass covers spec + manifest + prototype: the existing adversarial gap review plus the Playwright walk — every FLOW-XXX clickable, every SCR-XXX reachable, every P1 acceptance scenario has a path. One seat, one verdict; "does this flow serve the story" is judgment-shaped work and dominates the mechanical path-exists half, so adversarial-critique form fits (axis 5). The skeptic clicking the app is itself the adversarial move. Rejected: split qa-engineer walk (second seat for what one does en route) · mirror-checklist validator (grades the cheap half, leaves the judgment half homeless). Author≠grader holds: prototyper authors, devils-advocate grades.

**D6 — Producer seat: new staff-level agent + prototyping as a skill (Confident with user shaping, Q6 — posed with steelmans, no marked recommendation, after a flagged Q3–Q5 adoption streak).** New dedicated producer agent, but **not a prototyper-only persona**: staff-level engineering experience, team-capable alongside requirements-analyst; prototyping is a *skill* the agent accesses (`authoring-prototype`-shaped), per axis 4 — persona carries judgment, skill carries procedure, persona contains no trace of any workflow. Agents 8→9. Rejected: requirements-analyst absorbing it (persona stretch, intra-pair independence shaved) · staff-engineer moonlighting (keystone violation — TDD persona forced to suspend its own discipline; stage-identity blur).

**D5 — Contract surface: prototype dir + ID manifest (Confident, Q5).** `.mochiko/specs/<feature>/prototype/` holds the HTML/bun app; the spec gains a screens manifest enumerating **SCR-XXX** (screens: purpose, data shown) and **FLOW-XXX** (click-paths: step sequences, keyed to story acceptance scenarios). Plan traces to the IDs; the HTML is their clickable rendering. Manifest↔HTML drift is mechanically checkable — the stress-test seat's Playwright walk verifies every FLOW-XXX path exists in the served app. Rejected: HTML-as-manifest (source code as contract; binding-flow vs advisory-pixel indistinguishable in one artifact) · screenshots-only (kills clickability D1 and the implement-time conformance check D4).

**D4 — Plan-stage authority: binding flows, advisory pixels (Confident, Q4).** The accepted prototype's **click-paths and screen inventory are contract**: traced into plan's contracts/data-model (every screen's data needs a serving endpoint, every action a mutation path), flow-conformance checked at implement via Playwright. **Visual layout/styling stays advisory** — implement free to deviate cosmetically, no escalation. Rejected: architecture-grade full binding (pixel enforcement inverts low-fi's fidelity promise, cosmetic improvements would escalate) · spec-grade advisory-only (binds nothing, re-admits the surprise gap at implement).

**D3 — Conditionality: intent-ruled (Confident, Q3).** Prototype stage is conditional; the intent stage rules "UX-bearing: yes/no" as one more governing ruling (v0.49.0 intent stage already governs authoring, slicing, stress-test rigor). No → stage skipped, spec carries "No UX surface — prototype waived at intent." Rejected: always-on null path (UX-bearing is knowable up front, unlike quickstart's mid-plan-discoverable integration surface) · always-prototype-something (manufactured artifacts).

**D2 — Placement: lockstep co-evolution (Contested→ruled, Q2).** Prototype and stories co-evolve per-story: draft story + its screen(s) together, user clicks the slice while the story is wet, both settle, next story. Lead's recommendation was A (post-draft verification pass); contrasted A vs C at user's request under the Playwright-MCP fact — per-screen iteration cheap (seat renders, screenshots into chat; served bun app for flow checks), coordination penalty mostly dissolves under v8 lead-owned orchestration, and the driver is surprise *prevention* (per-story, draft-time) not *detection* (late gate). Lead reversed to C in the contrast; user ruled **C**. Known risks recorded: prototype thrash on shared nav/layout (mitigation: skeleton nav frame first, story screens fill in) · text-rigor erosion by drift toward prototype-first (discipline: pair moves together).

**D1 — Driver + fidelity (Confident, Q1).** Driver: specs give no good picture of UI/UX; "a lot of surprises" at build time. Artifact ruled: **clickable prototype** — low-fi HTML, run/served with **bun**, using the project's **design system if one exists**. Not text wireframes, not static images.

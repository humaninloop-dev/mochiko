### D1 — Seat tier is class-keyed by default; the lead may deviate per run with disclosure
**Statement:** Persona files stop carrying a uniform `model: opus`. The tiering skill gains a **seat default key**, sibling of D4's read key, with **two values — `strong` and `down`** — assigned per seat by one criterion: *does a structurally independent seat stand between this seat's output and the run's verdict?* Where it does, the seat may default down; where the seat *is* that independent check, it stays strong. Seats the criterion would send down but that the ruling holds strong are argued row by row in D3's ground column (there is no third class). Vocabulary: "class" names a value of this key — the `strong` class, the `down` class — and "class default" the alias that value pins; "seat default key" is the key itself. The lead may deviate from the default per seat per run, stating the reason in that seat's brief. Free lead judgment with no key, and a depth-keyed tier the lead cannot touch, are both rejected. *(Reworded per review G11 — the earlier "three-class" phrasing named a one-member class with no distinct default; the ruling is unchanged.)*
**Rationale:** The driver is cost with lead flexibility (Q1). A class key keeps the default predictable and eval-baselinable while the deviation lane keeps the tier the lead's call — the same shape `worker-seat-set-reserved` and D4 already use. Free judgment drifts the tier with whoever runs the command and leaves the persona evals with no baseline; depth-keying removes the lead's call entirely, which the driver names as wanted. Which seats fall in which class, and the exact default per class, are ruled below as their own decisions.
**Confidence:** Confident (user: "as recommended", with a follow-on question on the inheritance risk that D2 answers).

### D2 — The persona file carries the class default; the lead's decision is an explicit spawn-time override, disclosed; no `inherit`, no hook
**Statement:** No mochiko persona carries `inherit` or an absent `model:`. Each persona file pins its **class default** as an alias (`opus` for the strong class, `sonnet` for the down class — D3 assigns seats), which sits above `CLAUDE_CODE_SUBAGENT_MODEL` and above inheritance in both resolution orders (F12) from Claude Code v2.1.251 (F17), absent `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (F14) and an `availableModels` substitution (F15) — FORCE left as the consumer's own environment (G1); the allowlist an organization control left undetected in-run (G5, G12). The lead selects by passing `model:` on the spawn **only when deviating** from the class default, and states the deviation and its reason in that seat's brief and in the run's seat roster line. `override-is-the-pin` extends from the two dispatch rungs to seats: a seat spawn is either the class default (no override) or a disclosed deviation; an undisclosed override has failed the floor. No mechanical gate on model-less spawns — a `PreToolUse` deny on `Agent` blocks dispatch, which GI-019's bright line names kernel-class; hooks also fail open. The plan-only command evals may *observe* whether a lead's plan names a tier per seat (a watch), never gate it.
**Rationale:** The user's question — can the model be silently inherited, and how do we make the lead decide — has a structural answer: put the ruled default where a forgotten decision lands. With `inherit`, a forgotten override takes the lead's model in either direction (Fable seats at 2× Opus cost; Sonnet graders under a Sonnet lead) and a user's env var retiers every seat, all silently. With the file default, forgetting costs only the deviation the lead meant to make, never correctness. The override lane is session-evidenced on personas (F13) and doc-quoted on teammates (F12). Rejected: `inherit` anywhere (silent bidirectional drift); a deny hook (kernel-class without a ruling; fail-open); making every spawn carry `model:` unconditionally (redundant with the file default and forgettable — the 2026-08-16 ADR's own argument for a file pin).
**Confidence:** Confident (user ruled option 1 conditional on the dry run; the dry run passed on the transport it could reach — and, per F16, on the in-process teammate transport as well).

**Statement:** Class defaults per persona, pinned as aliases in frontmatter (D2):

Haiku is never a seat default (200K context; not a reliable coder — ADR 2026-09-05). Fable is never a default (the driver is cost; up-tiering was declined at Q1) but stays available to the lead's deviation lane.
**Rationale:** The key is "does an independent grader stand between this seat's output and the run's verdict".

## Decisions

- **D1 — Cycles anchor on test-case bundles, walking skeleton first.** `Confident` (user-ruled Q4, adopting the lead's recommendation)
  A cycle is a coherent bundle of named, design-time-defined test cases (expected behaviour, Given/When/Then grain, executable Setup/Action/Assert form) that demonstrate together to the user; cycle-done = those cases shown green against real infrastructure (actual behaviour = captured evidence). Standing first-cycle rule: a walking skeleton — the thinnest end-to-end path through all layers with one trivial case green. No demonstrable bundle → no cycle; merge until a bundle is worth demonstrating. Cycle count is anchored on demos worth watching — the time-based sizing tables (SKILL.md "1–3 sessions", reference "1–3 hours" / "<30 min" merge bar) and the proliferating worked examples (CRUD=4, Search=6, Auth=7 with horizontal foundation layers) are superseded by this anchor.
  *Skeleton carve (M2 fold, user-ruled):* the walking-skeleton first-cycle rule applies where no end-to-end path yet exists for the work — greenfield features or a genuinely new path through the system. Growth/delta work on an already-standing path skips the skeleton cycle (bug fixes were already outside this skill's scope).
  *Rationale:* user's felt pain is cycle count (Q1); fixed per-cycle overhead multiplies with count (F8); the current sizing guidance itself teaches the proliferation (F6/F7); the user explicitly wanted cycles tied to clearly defined test cases demonstrable to the user (Q2).
  *Minimal-fix baseline weighed (I4 fold, user-ruled):* repairing the F6/F7 defects alone (aligning the sizing tables, rewriting the examples vertical) was considered and is insufficient — it would keep the human-hours time anchor and the story-anchored default, and the user's Q2 direction was an anchor change (demonstrable test cases), not a calibration repair. The re-key is required by the ruling, not by the defects.

- **D2 — qa-engineer authors the design-time test cases; the design seat keeps the slicing judgment; plan review gains an oracle-semantics check; staff-engineer keeps build-time unit tests.** `Confident` (user-ruled Q4; amended at review — I1/I2/I3/I7 folds, user-ruled batch)
  The qa-engineer gains a design-time seat in the plan run: it authors the cycle cards' **test-case content** (expected behaviour) in the same executable grammar it later runs. **Authorship split (I7 fold):** the slicing judgment — which bundles exist, Simple/Split/Merge calls, inter-card dependencies, the walking-skeleton call — stays with the design seat running `patterns-vertical-tdd`; QA authors the cases within those cards. One card surface, two authors, each owning their craft. **Oracle independence (I1 fold):** D2 collapses today's author≠executor pair on the acceptance oracle (design-time author, QA executor) into one seat; to compensate, plan review gains an explicit **oracle-semantics clause** — each Assert is graded semantically against the acceptance scenario it cites (does it capture the *right* expected behaviour), not merely for shape/presence. Staff-engineer's red-phase unit/integration tests are untouched — two test layers: QA's acceptance cases (card content, user-facing demo) and staff's unit tests (implementation detail).
  *Rationale (as amended, I2 fold):* executor-authored cases are executable by construction (QA owns the Setup/Action/Assert grammar it consumes); verification-minded authorship covers edge cases and failure modes a building mind skips; the expected-vs-actual diff QA presents at checkpoint is exactly the demonstration D1 anchors cycles on. *(Struck at review: "keeps the implementation from shaping its own oracle" — false premise; the oracle was already implementer-independent per F4, and staff's unit tests are kept regardless.)*
  *Coupling weighed (I3 fold):* D2 adds one design-time seat and one plan-run handoff — a one-time-per-plan cost — in a session whose goal is cutting complexity; D1/D3 remove per-cycle multiplication of the F8 overhead (the kinako-s1 12-cycle shape collapses toward skeleton + a few bundles). Net complexity effect strongly negative; recorded so the trade-off is on the ruling, not behind it.

- **D3 — Foundation/feature classification dies as a card type.** `Confident` (user-ruled Q5, "kill as suggested")
  The walking skeleton is the foundation — one cycle, by construction; where a skeleton cycle exists at all (per D1's greenfield/new-path carve), it is the first cycle. All later cycles are test-case bundles; infrastructure a bundle needs emerges inside the first bundle that needs it (YAGNI at cycle grain). Inter-card dependencies stay explicit; `[P]` parallel eligibility derives from dependencies, not from a type column. The foundation-identification question ("could ANY story work in production without this?"), the foundation/feature type field, and the reference's foundation stacks (Auth C1–C3 etc.) are superseded.
  *Rationale:* the foundation type was the licence under which horizontal layer-stacks were minted as cycles (F7; kinako s1's 12 cycles); the skeleton absorbs the sequencing role the type existed for; an informational label was considered and rejected — it invites the old habit of infra-only cycles.
  *Platform-infrastructure homing (I6 fold, user-ruled):* IP-XXX platform provisioning is not left homeless by the type-kill — provisioning the walking-skeleton path crosses lands **in the skeleton cycle** (the skeleton deploys production-shaped, so its path's infra is its content); all remaining infrastructure lands **inside the first bundle that needs it**. Infra-only cards are never minted.

- **D4 — `**TEST:**` grammar ownership stays with `patterns-vertical-tdd`; QA authors within it.** `Assumed` (lead working assumption stated at Q5, not objected to; sustained at review)
  The grammar (Setup/Action/Assert fields, modifiers, classification) remains owned by the design-time slicing skill; the qa-engineer's design-time seat authors test cases in that grammar. Downstream parsers (`testing-end-user`, `executing-tdd-cycle`) keep consuming it unchanged. *(M4 fold note: relocating grammar ownership toward a QA-side skill now that authorship moved was raised at review and not tested — it stays an untested alternative on this `Assumed` mark, revisitable at build.)*
